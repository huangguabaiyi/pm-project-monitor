# 卡片未确定排期环节展示设计

日期：2026-08-03

## 1. 目标

当项目产生低缓冲、负缓冲或合板窗口不足风险时，卡片不再展示“环节：未标注”，而是明确展示哪些关键环节尚未确定排期。

## 2. 未确定排期定义

以下两类关键环节视为未确定排期：

1. 当前或未来的 AT1、AT2、PV1、PV2、线上回归没有进展节点行，排期引擎使用虚拟环节计算。
2. 已存在进展节点，但未填写计划完成时间，排期引擎使用项目配置或固定默认时长计算。

已填写计划完成时间的节点不属于未确定排期。已完成或已跳过节点不属于未确定排期。

## 3. 风险数据

- 域排期计算时，从参与计算的未完成阶段中提取未确定排期环节。
- 将这些环节写入低缓冲、负缓冲和合板窗口不足类 finding 的 `stage_refs`。
- 多交付域的相同风险合并时，对环节去重并按照基础配置中的流程顺序展示。
- 不改变风险等级、预计完成时间、缓冲和延期计算结果。

## 4. 卡片展示

对于以下排期风险：

- `schedule.buffer_low`
- `schedule.buffer_negative`
- `schedule.minimum_window_insufficient`
- `domain.completion_after_merge`

当 finding 包含未确定排期环节时，卡片使用“未确定排期”标签；其他风险仍使用“环节”标签。

示例：

```text
1. 剩余缓冲不超过2天
未确定排期：PV 测试第一轮、PV 测试第二轮、线上回归
交付域：平台、客户端、服务端
```

## 5. 验收标准

- 虚拟关键环节会出现在“未确定排期”中。
- 已建节点但缺少计划完成时间的关键环节会出现在“未确定排期”中。
- 已填写计划完成时间的环节不会出现在“未确定排期”中。
- 多交付域相同风险的环节会合并去重并按流程排序。
- 卡片不再为这类风险显示“环节：未标注”。
- 现有风险计算和其他类型卡片展示不受影响。
