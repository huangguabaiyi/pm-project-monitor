# 需求进展监控与飞书提醒工具设计

## 1. 背景与目标

团队需求需要依次经过需求撰写、评审、设计、宣讲、排期、开发、联调、提测、测试、线上回归和版本合入。不同成员可能同时承担多个任务，如果没有持续暴露交付节点和截止时间，早期延期容易挤压后续测试和上线窗口。

本工具以飞书多维表格作为人工维护入口，每个工作日定时读取最新进展，通过确定性规则评估延期和上线风险，再使用 Webhook 机器人发送飞书卡片。LLM 仅增强摘要、风险解释和行动建议；LLM Token 过期、超时或模型服务不可用时，基础计算和消息推送必须继续运行。

核心目标：

- 明确展示每位负责人的近期交付节点和 DDL。
- 识别节点延期、测试周期不足、阻塞超期和合板风险。
- 表达服务端、客户端、车辆等交付域中研发与测试的配套关系。
- 支持项目级测试周期差异，同时保留统一的固定业务规则。
- 允许成员直接在线编辑飞书多维表格，减少额外系统的使用成本。
- 单条错误数据、LLM 故障或卡片格式问题不得拖垮整批提醒。

## 2. 范围与非目标

### 2.1 第一版范围

- 维护需求、进展节点、阻塞项和项目配置。
- 工作日北京时间 20:00 自动检查并发送日报。
- 支持本机命令人工执行一次检查。
- 支持普通、预警、严重三级风险。
- 使用现有飞书工具读取和维护多维表格。
- 使用 Webhook 发送互动卡片，并在必要时降级为精简卡片或纯文本。
- 在 Mac 登录后自动运行，可通过命令启动、停止、重启和查看状态。

### 2.2 非目标

- 不建设完整项目管理看板。
- 不维护复杂前置依赖、工作量分解、验收流程或资源负载模型。
- 不通过 Webhook 机器人接收上行命令。
- 不在 Mac 错过 20:00 后自动补发日报。
- 第一版不自动识别法定节假日和调休。
- 第一版按一个需求对应一个版本和一个统一合板时间处理，但数据结构预留后续多版本拆分能力。

## 3. 已知业务流程

默认流程如下：

1. 需求撰写
2. 内部评审
3. 产品需求评审
4. 设计稿输出
5. 设计宣讲
6. 需求宣讲
7. 工作量评估排期
8. 各端开发
9. 联调
10. 提测
11. AT 测试第一轮
12. AT 测试第二轮
13. PV 测试第一轮
14. PV 测试第二轮
15. 线上回归
16. 版本合入

参与方包括客户端、服务端、中枢平台、嵌入式、插件、助手、车辆及其他在开发过程中确认的团队。服务端、客户端和车辆等交付域分别具有研发和测试角色；各测试角色可以使用不同排期，但最终共享需求主表中的合板时间。

## 4. 固定业务规则与项目差异

本地 `固定业务规则`文件是只读默认基线，LLM 和程序均不得修改。当前规则包括：

- 服务端上线时间固定为每周二和周四。
- 服务端上线前一天必须提交 Checklist。
- 服务端 17:30 后禁止上线。
- AT 两轮测试周期一般不少于一周半。
- PV 测试约 3 天，并预留 2 天修复 Bug，合计约 5 天。
- 线上回归约 3 天。

周期默认按工作日计算，项目可以切换为自然日。工作日模式第一版只跳过周六和周日。

固定规则的确定性换算为：

- AT 两轮合计：工作日模式至少 8 个工作日，自然日模式至少 11 个自然日。
- PV 与 Bug 修复：默认合计 5 天。
- 线上回归：默认 3 天。

项目差异通过“项目配置表”的结构化字段覆盖。优先级为：

`项目结构化参数 > 固定业务规则 > 系统安全默认值`

项目补充说明是仅供 LLM 使用的自然语言上下文，不直接参与底线日期计算。

## 5. 系统架构

系统由六个模块组成。

### 5.1 数据读取器

- 直接调用本机已安装并认证的飞书工具读取和更新多维表格。
- 读取本地只读的`固定业务规则`文件。
- 过滤需求宣讲未完成、禁止通知或已经归档的需求。

### 5.2 数据校验器

- 检查数据表、必填字段、字段类型、关联记录和日期格式。
- 单条错误记录被跳过，其他有效需求继续处理。
- 关键表或关键字段不存在时停止本次进展计算，避免误报。

### 5.3 确定性规则引擎

- 合并固定业务规则和项目结构化参数。
- 计算节点延期、剩余缓冲、测试周期是否充足、阻塞是否超期、上线时间是否合法。
- 按交付域独立计算风险，需求总体风险取最高等级。
- 完全不依赖 LLM。

### 5.4 LLM 增强器

- 输入结构化进展、自然语言进展、固定业务规则和项目补充说明。
- 文档类输入仅允许读取本地`固定业务规则`文件，不搜索或读取其他飞书文档、云盘文件或本地文档。
- 输出摘要、补充风险、影响分析和行动建议。
- 只能提升风险等级，不能降低规则引擎等级或修改日期计算结果。
- Token 过期、限流、超时、空结果或格式错误时跳过增强。

### 5.5 卡片生成与发送器

- 生成每日进度、预警、严重风险和数据异常卡片。
- 普通和预警信息 @ 当前负责人，严重风险 @ 项目负责人。
- 卡片生成失败时依次降级为精简卡片和纯文本。

### 5.6 运行记录与告警器

- 记录每次读取、校验、计算、LLM 调用和 Webhook 响应。
- 使用通知指纹避免同一风险短时间重复发送。
- 保存本地运行状态，并将可写入的结果同步到通知记录表。

完整链路：

`定时或人工触发 → 读取表格与固定规则 → 校验 → 规则计算 → 可选 LLM 增强 → 卡片生成 → Webhook 发送 → 记录结果`

## 6. 飞书多维表格设计

采用六张表，其中成员主要维护需求主表、进展节点表和阻塞项表。

### 6.1 需求主表

每条记录代表一个需求在一个版本中的整体交付。

人工维护字段：

- 需求编号
- 需求名称
- 项目名称
- 当前环节
- 项目负责人
- 产品负责人
- 目标版本
- 合板时间
- 计划上线时间
- 需求宣讲是否完成
- 是否允许通知
- 是否归档
- 项目配置关联
- 需求补充说明
- 备注

系统字段：

- 当前风险等级
- 风险原因
- 预计完成时间
- 剩余缓冲天数
- 最近检查时间
- 最近通知时间

通知资格必须同时满足：

- 需求宣讲已经完成。
- 是否允许通知为“是”。
- 是否归档为“否”。

### 6.2 进展节点表

统一承载公共流程、各端研发、联调、提测、测试和发布节点。

人工维护字段：

- 关联需求
- 交付域
- 工作类型
- 节点名称
- 负责人
- 计划开始时间
- 计划完成时间
- 实际完成时间
- 当前状态
- 进展说明
- 最后更新时间

系统字段：

- 系统风险等级
- 系统风险原因
- 最晚安全 DDL

交付域预置值：

- 公共流程
- 客户端
- 服务端
- 车辆
- 中枢平台
- 嵌入式
- 插件
- 助手
- 其他

工作类型预置值：

- 公共环节
- 研发
- 测试
- 联调
- 发布

研发与测试通过相同的交付域形成配套关系。例如“服务端研发”“服务端 AT1”“服务端 AT2”均属于服务端交付域。允许某个交付域只有研发、只有测试或增加额外测试轮次。

如果需求包含服务端交付域，则应包含“服务端 / 发布 / 上线 Checklist”节点。该节点的计划完成时间由系统根据上线日期计算为前一天，成员只需维护负责人、状态和实际完成时间。

### 6.3 阻塞项表

人工维护字段：

- 关联需求
- 阻塞事项
- 关联节点
- 责任人
- 发现时间
- 计划解决时间
- 实际解决时间
- 当前状态
- 是否影响合板
- 处理说明

风险等级由系统计算，不要求成员手工填写。

### 6.4 项目配置表

每个项目一条记录。

- 项目名称
- 周期计算方式：工作日或自然日
- AT 最少测试天数
- PV 最少测试天数
- Bug 修复预留天数
- 线上回归最少天数
- 服务端专项测试天数
- 客户端专项测试天数
- 车辆专项测试天数
- 可上线日期
- 上线截止时间
- 是否启用 LLM
- 项目补充说明

Checklist 提前天数不提供项目配置，始终使用固定业务规则中的“上线前一天”。

### 6.5 基础配置表

管理员低频维护：

- 配置类型：环节、交付域、工作类型或测试角色
- 配置名称
- 排序
- 是否启用
- 备注

新增参与方、专项测试或流程节点时增加配置记录，不增加主表字段。

### 6.6 通知记录表

由程序自动写入：

- 需求
- 通知类型
- 风险等级
- 消息摘要
- 通知对象
- 发送时间
- 发送结果
- 错误信息
- 是否使用 LLM
- LLM 降级原因
- 通知指纹

## 7. 风险计算规则

### 7.1 配套域计算

服务端、客户端、车辆及其他交付域分别计算研发和测试的预计完成时间。所有交付域共享需求合板时间。

`需求预计完成时间 = 所有交付域预计完成时间中的最晚值`

`需求风险等级 = 所有节点、交付域和阻塞项风险中的最高等级`

### 7.2 普通

以下条件同时成立时为普通：

- 当前节点未超过计划完成时间。
- 未完成节点的最低所需周期可以在合板前完成。
- 没有超期阻塞项。
- 最近进展在合理时间内更新。
- 上线日期符合固定规则。

普通信息在日报中展示并 @ 当前负责人。

### 7.3 预警

出现任一情况进入预警：

- 节点已经延期，但剩余缓冲仍能覆盖。
- 距离合板的剩余时间只比最低所需周期多 2 个工作日以内。
- 阻塞项将在 1 个工作日内到期。
- 当前节点连续 2 个工作日没有进展更新。
- 测试排期尚未填写，但已经接近应开始时间。
- LLM 给出明确、可解释的潜在风险理由。

预警在日报中展示并 @ 当前负责人。

### 7.4 严重

出现任一情况进入严重风险：

- 按最低周期计算也无法赶上合板时间。
- 任一交付域预计完成时间晚于统一合板时间。
- 测试周期低于项目配置或固定规则下限。
- 影响合板的阻塞项超过计划解决时间。
- 节点延期已经耗尽全部缓冲。
- 服务端计划上线日期不是周二或周四。
- 服务端计划上线时间晚于 17:30。
- 服务端上线前一天仍未完成 Checklist。
- LLM 在已有数据基础上识别出明确的合板或上线影响。

严重风险使用独立卡片并 @ 项目负责人，同时展示节点负责人和阻塞责任人。

### 7.5 LLM 边界

LLM 可以将普通升级为预警或严重，也可以将预警升级为严重，但必须输出理由并标记为“AI 补充判断”。LLM 不得降低风险等级、修改排期、修改固定业务规则或阻断基础通知。

### 7.6 通知去重

通知指纹包括需求、交付域、节点或阻塞项、风险等级、计划完成时间和预计延期时间。

以下变化允许重新产生风险提醒：

- 风险等级上升。
- 负责人变化。
- 计划时间变化。
- 预计延期天数增加。
- 阻塞解决时间变化。
- 风险解除后再次出现。

由于第一版不进行日内自动扫描，风险变化会在下次工作日 20:00 或人工执行 `run-once` 时被发现。

## 8. 飞书卡片设计

### 8.1 每日进展卡片

每日按项目发送，并按负责人分组。展示范围为：

- 今日到期和已经逾期的节点置顶。
- 展示每位负责人未来 7 天内的全部未完成节点。
- 7 天以后的节点仅展示待办数量。
- 同一负责人有多个并行节点时全部展示。

每条节点使用固定结构：

`@负责人｜需求｜交付域｜节点｜计划 DDL｜最晚安全 DDL｜状态`

卡片头部展示日期、需求数量以及普通、预警、严重数量。内容中同时展示目标版本、合板时间、上线时间、剩余缓冲和阻塞摘要。普通和预警节点 @ 当前负责人。

### 8.2 严重风险卡片

单个需求单独发送，使用红色标题并展示：

- 需求、项目和版本
- 统一合板时间
- 当前预计完成时间
- 预计延期天数
- 受影响交付域
- 规则引擎判定原因
- 阻塞项和责任人
- 必须执行的下一步动作
- 最晚处理时间
- 节点负责人和项目负责人

严重风险重点 @ 项目负责人。

### 8.3 数据异常卡片

展示表名、需求、记录标识、错误字段、当前错误值、预期格式、修复建议和是否跳过该需求。

### 8.4 LLM 降级提示

当 LLM 不可用时，基础卡片照常发送，卡片底部显示“AI 补充分析不可用，基础规则正常运行”。

## 9. 调度与本机运行

第一版运行在用户 Mac 上：

- 登录系统后通过 macOS `launchd` 自动运行。
- 工作日北京时间 20:00 执行一次完整检查。
- 周末不自动发送日报。
- 20:00 时处于关机或休眠状态则不补发。
- 自动任务执行时校验触发时间窗口，避免 `launchd` 在休眠恢复后补跑已经错过的日报。
- 用户可以人工执行一次检查。
- 不启动对外 Web 服务，不依赖 Webhook 上行链路。

命令接口：

```bash
requirement-monitor start
requirement-monitor stop
requirement-monitor restart
requirement-monitor status
requirement-monitor run-once
requirement-monitor logs
```

`start`注册并启动后台任务，`stop`终止并取消自动运行，`restart`重新加载配置，`status`展示运行状态和最近结果，`run-once`立即执行一次但不改变后台状态，`logs`查看运行和错误日志。

## 10. 配置与安全

本机配置包括：

- 多维表格地址和目标表标识
- 测试或正式 Webhook
- LLM API 地址、模型名称和 Token
- 默认发送时间和时区
- 固定业务规则文件路径
- 本地日志目录

Webhook 和 LLM Token 不写入多维表格或代码仓库。飞书表格读写直接使用本机已经认证的飞书工具。

每次执行前检查飞书工具认证状态。认证失效时停止本次计算，并在 Webhook 可用时发送“飞书表格认证失效”异常信息。LLM 认证与飞书工具认证相互独立。

## 11. 异常处理与降级

### 11.1 表格异常

- 单条记录错误：跳过该记录，其他需求继续处理。
- 单张表部分字段错误：尽量处理有效字段，并发送异常卡片。
- 关键表或关键字段不存在：停止本次进展计算，只发送系统异常。
- 飞书工具认证失效：停止计算，通过 Webhook 报告并写本地日志。

### 11.2 LLM 异常

- Token 过期、额度不足、超时、限流、空内容和格式错误均进入无 LLM 模式。
- 规则引擎结果和基础卡片继续执行。
- 记录具体降级原因。

### 11.3 卡片和 Webhook 异常

发送前进行本地结构校验，并按以下顺序降级：

1. 完整互动卡片。
2. 精简卡片。
3. 纯文本消息。

Webhook 网络或服务错误重试三次，建议间隔为 10 秒、30 秒和 2 分钟。连续失败后写入本地日志；表格仍可写时同步写入通知记录表。旧日报不在下一次自动补发。

如果唯一 Webhook 本身不可用，系统无法通过同一机器人报告自身故障，因此必须依靠本地日志和 `logs` 命令排查；正式部署后可选配独立备用告警 Webhook。

## 12. 测试方案

### 12.1 规则测试

- 需求宣讲未完成时不通知。
- 已归档需求不通知。
- 项目参数正确覆盖固定规则。
- 工作日和自然日模式正确计算。
- 服务端上线日期和 17:30 截止规则正确。
- Checklist 计划时间正确生成。
- 各交付域独立计算，需求风险取最高等级。
- LLM 只能升级风险。
- 通知指纹正确去重。

### 12.2 表格测试

- 通过现有飞书工具读取多张表。
- 成员在线编辑后能读取最新数据。
- 新增交付域、测试角色或流程节点无需修改代码。
- 单条日期或关联记录错误不影响其他需求。
- 系统字段和通知记录正确回写。

### 12.3 卡片测试

使用测试 Webhook 验证普通日报、预警、严重风险、数据异常、LLM 降级和纯文本降级消息。

### 12.4 故障测试

- LLM Token 失效或超时。
- 飞书工具认证失效。
- 表格字段缺失或类型错误。
- Webhook 返回错误或网络不可用。
- 后台程序被停止和重新启动。
- Mac 在 20:00 关机或休眠，确认不补发。

## 13. 验收标准

1. Mac 登录后自动运行，可通过命令启动、停止、重启和查看状态。
2. 工作日北京时间 20:00 自动发送，错过后不补发。
3. 支持命令立即执行一次检查。
4. 每个人未来 7 天内的交付节点、计划 DDL 和最晚安全 DDL 清晰可见。
5. 服务端、客户端、车辆等交付域的研发和测试按配套关系展示。
6. 普通和预警消息 @ 节点负责人，严重风险 @ 项目负责人。
7. LLM 完全失效时基础风险计算和推送仍正常。
8. 单条错误数据不会影响其他需求。
9. 卡片失败时能够降级为纯文本。
10. 需求宣讲未完成和已归档需求不发送通知。
11. 所有发送结果、LLM 降级和错误均可追踪。
12. 成员可以直接在飞书多维表格中维护业务数据，不需要额外管理后台。
