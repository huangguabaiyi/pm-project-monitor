# 人工计划完成时间优先与虚拟环节排期设计

日期：2026-08-03

## 1. 目标

- 已填写计划完成时间的节点完全采用人工排期，不再用默认时长校验或延长。
- 已创建但未填写计划完成时间的节点使用项目配置时长，项目配置为空时使用固定默认时长。
- 当前环节及后续缺少的关键测试环节以虚拟环节参与预计完成时间、缓冲和延期计算。
- 虚拟环节不代表未通过，不产生门禁失败，不 @ 人，也不写入进展节点表。
- 排期只计算 AT1、AT2、PV1、PV2、线上回归以及显式节点日期，不再增加独立的额外预留阶段。

## 2. 排期优先级

1. `已完成`：使用实际完成时间；没有实际完成时间时使用计划完成时间。
2. `已跳过`：时长为零，视为通过。
3. 未完成且填写计划完成时间：使用 `max(当前计算游标, 计划完成时间)`，默认时长不参与该节点计算。
4. 未完成且没有计划完成时间：从计划开始时间或当前计算游标开始，加项目配置或固定默认时长。
5. 关键环节没有节点：从当前环节开始为缺少的 AT1、AT2、PV1、PV2、线上回归生成只读虚拟环节，并按配置时长计算。

## 3. 虚拟环节范围

- 只补算当前环节及后续环节，不补算已经经过的历史环节。
- 默认时长：AT1 4、AT2 4、PV1 3、PV2 2、线上回归 2 个工作日。
- 基础配置中停用的环节不生成虚拟环节。
- 多交付域并行计算，各域分别形成路径，需求预计完成时间取最晚路径。
- 没有任何进展节点时使用“项目排期”虚拟路径计算。

## 4. 风险语义

- 缺少节点本身只生成流程补充提醒。
- 虚拟环节使预计完成时间超过合板时，可以产生“预计完成晚于合板”或“剩余缓冲为负”等排期风险。
- 已填写计划完成时间但周期短于默认时长，不再产生“测试周期低于最低要求”。
- 已创建的 AT/PV/线上回归节点仍按状态执行门禁；未创建节点不视为门禁失败。

## 5. 配置与数据范围

- 项目配置只保留 AT1、AT2、PV1、PV2、线上回归五项回退时长。
- 固定业务规则明确列出 `4/4/3/2/2` 个工作日，不从其他阶段或自然语言说明推导时长。
- 关键路径公式只展示真实节点日期和上述五个阶段，不增加独立的额外排期项。

## 6. 验收

- 人工结束时间存在时，预测结果不因默认时长后移。
- 人工结束时间缺失时，预测结果使用配置时长。
- 缺少后续节点时仍能完整计算 AT1、AT2、PV1、PV2、线上回归路径。
- 缺少节点不产生“未通过”风险，但虚拟路径超出合板时产生真实排期风险。
- 全量测试通过，线上 dry-run 公式只包含真实节点日期和 AT1、AT2、PV1、PV2、线上回归阶段。
