# 需求进展监控工具 v3 改版设计

## 1. 文档状态

- 状态：已获用户批准，待进入实现计划阶段
- 基线设计：`2026-07-27-requirement-progress-monitor-v2-design.md`
- 本次范围：真实链接提取、测试/正式 Webhook 隔离、风险原因按环节归并
- 设计原则：不依赖 LLM，不影响现有飞书多维表格维护方式，不使用浏览器或上行 Web 服务

## 2. 背景与目标

当前工具已经可以从飞书多维表格读取需求和进展节点，计算确定性风险并发送飞书卡片。本次改版解决三个问题：

1. 飞书 URL 字段可能返回“文档名称”等展示文本，当前解析器会把展示文本误当成 URL，导致需求被判定为数据错误。
2. 测试环境和正式环境共用 Webhook，容易在开发调试时误发正式消息，也无法形成正式环境只能从 `main` 分支使用的安全边界。
3. 风险原因目前以长字符串列表输出，重复、难读，无法快速看出同一风险影响哪些环节和交付域。

本次改版目标：

- 只使用飞书字段中的真实链接，展示文本不再参与 URL 校验。
- 测试 Webhook 与正式 Webhook 完全隔离，正式 Webhook 在非 `main` 分支不可使用。
- 将同类风险按归一化原因分组，并集中展示影响环节和交付域。
- 保留所有风险分类，不因卡片布局收敛而静默丢失信息。
- 继续保证 LLM 失效时，确定性规则和底线推送可以独立运行。

## 3. 范围与非目标

### 3.1 本次范围

- 增加运行环境选择和双 Webhook 配置。
- 增加正式环境的 Git 分支安全校验。
- 重构三类需求链接字段的真实 URL 提取。
- 保留链接字段可选语义。
- 增加结构化风险发现和风险原因分组展示。
- 更新普通日报、严重风险卡片及相关文档。
- 增加配置、链接、风险聚合和卡片输出测试。

### 3.2 非目标

- 不新增 Webhook 上行接口或机器人命令能力。
- 不把正式 Webhook 写入 Git 跟踪文件、示例配置或测试代码。
- 不使用 LLM 进行 URL 提取或风险归并；归并结果必须可重复、可测试。
- 不改变多维表格的基础字段结构，只调整读取、校验和输出逻辑。
- 不改变现有需求过滤规则：未完成需求宣讲、已关闭通知或已归档需求仍不发送。

## 4. 总体架构

```text
飞书多维表格
    │
    ▼
数据读取与字段解析
    ├─ 需求、节点、阻塞项解析
    ├─ 飞书 URL 真实链接提取
    └─ 数据异常按记录隔离
    │
    ▼
确定性风险计算
    ├─ 当前环节校验
    ├─ AT/PV/线上回归门禁
    └─ 生成结构化 RiskFinding
    │
    ▼
风险聚合与卡片渲染
    ├─ 按风险原因归一化
    ├─ 合并影响环节与交付域
    └─ 多区块卡片展示
    │
    ▼
环境安全门
    ├─ test → 测试 Webhook
    └─ prod → 仅允许 main 分支 → 正式 Webhook
    │
    ▼
飞书 Webhook
```

模块边界：

- `config`：解析运行环境、Webhook 和安全词配置。
- `repository`：读取飞书字段并提取真实 URL，不向上层暴露飞书展示对象。
- `risk`：生成带来源环节和交付域的结构化风险发现。
- `cards`：只负责将结构化风险发现渲染成卡片，不从长文本猜测环节。
- `runner`：选择环境、执行分支校验、发送卡片并记录结果。

## 5. 双 Webhook 与环境隔离

### 5.1 配置项

新增环境变量：

```text
REQUIREMENT_MONITOR_TEST_WEBHOOK_URL
REQUIREMENT_MONITOR_PROD_WEBHOOK_URL
REQUIREMENT_MONITOR_ENV
REQUIREMENT_MONITOR_BOT_KEYWORD
```

运行环境允许值为 `test` 和 `prod`，默认值为 `test`。安全词由两个环境共用，但仍通过环境变量读取，不写入 Git 跟踪文件。

旧变量 `REQUIREMENT_MONITOR_WEBHOOK_URL` 仅作为兼容配置使用，并只映射到 `test` 环境。正式环境不得通过旧变量提供 Webhook。

### 5.2 命令行为

```bash
.venv/bin/requirement-monitor run-once --env test
.venv/bin/requirement-monitor run-once --env prod
.venv/bin/requirement-monitor start --env test
.venv/bin/requirement-monitor restart --env prod
```

命令行参数优先级高于 `REQUIREMENT_MONITOR_ENV`，环境变量高于默认值。若运行环境没有明确指定，使用 `test`，不得自动推断为 `prod`。

### 5.3 正式环境安全校验

当运行环境为 `prod` 时：

1. 读取当前工作目录对应 Git 仓库的当前分支。
2. 只有分支名称严格等于 `main` 时通过。
3. `feature/*`、`develop`、其他分支、detached HEAD 或无法读取分支时拒绝发送。
4. 拒绝时不降级为测试 Webhook，不生成发送记录，不写业务系统字段。

该校验约束“只能在 main 分支使用正式 Webhook”，不额外验证远程仓库是否已 push，也不要求工作区干净；是否提交和合入由发布流程负责。

### 5.4 后台任务

`start` 和 `restart` 在加载 LaunchAgent 前完成：

- 环境解析；
- 对应 Webhook 读取；
- 安全词读取；
- `prod` 分支校验；
- 私密 runtime snapshot 写入。

后台 `scheduled-run` 只读取已校验的 snapshot，不依赖 LaunchAgent 继承当前终端环境。snapshot 保持现有 `0600` 权限和原子写入策略。

## 6. 飞书真实 URL 提取

### 6.1 适用字段

- `需求文档链接`
- `Meego链接`
- `多语言翻译链接`

三个字段仍然是可选字段。空值不产生错误，不显示对应卡片按钮。

### 6.2 提取优先级

新增统一的 `extract_real_url(value, field_name)` 逻辑：

1. 字段为映射对象时，按 `link`、`url`、`href` 顺序查找真实链接。
2. 映射对象中的 `value` 只有在自身是完整 HTTP/HTTPS URL 时才使用。
3. 字段为列表时递归查找第一个有效真实链接。
4. 字段为原始字符串时，只有完整 HTTP/HTTPS URL 才作为链接。
5. `text`、`name`、`title` 以及仅含文档名称的 `value` 只能作为展示信息，不能作为 URL。
6. 对提取结果校验协议为 `http` 或 `https`，并要求存在网络位置。

示例：

```json
{
  "text": "需求文档",
  "link": "https://mi.feishu.cn/docx/xxx"
}
```

解析结果为：

```text
https://mi.feishu.cn/docx/xxx
```

以下值视为“没有真实链接”，不报错：

```json
{"text": "需求文档"}
```

以下值视为非法非空 URL，隔离当前需求：

```text
这是一个错误链接
```

### 6.3 错误隔离

- 展示名称替代真实链接：按空值处理。
- 真实链接缺失：按空值处理。
- 非空真实链接格式非法：生成字段级 `ValidationIssue`，隔离当前需求。
- 需求文档链接、Meego 链接、多语言翻译链接相互独立；一个字段错误不影响其他需求。
- 原始飞书对象只存在于 repository 层，模型和 cards 层只接收 `Optional[str]` 真实 URL。

### 6.4 卡片行为

卡片只对解析后的真实 URL 创建按钮：

- `需求文档`；
- `Meego`；
- `多语言翻译`。

展示名称不会被渲染成不可点击的假链接，也不会作为按钮地址发送。

## 7. 结构化风险发现与归并

### 7.1 风险发现模型

风险计算层生成结构化 `RiskFinding`，至少包含：

```text
reason_code
reason_text
stage_refs
domain_refs
level
source
```

其中：

- `reason_code` 是稳定的确定性规则标识；
- `reason_text` 是用户可读的风险原因；
- `stage_refs` 是流程环节或节点名称；
- `domain_refs` 是客户端、服务端、车辆等交付域；
- `level` 是普通、预警或严重；
- `source` 用于定位来自节点、测试门禁、阻塞项或排期计算。

保留现有 `reasons` 字段作为兼容输出，但卡片优先使用结构化风险发现，不从自然语言风险长句反向猜测环节。

### 7.2 归一化规则

按 `reason_code` 优先归并。对于尚未配置稳定编码的历史文本，使用受控模板归一化；无法识别的文本按原文精确去重。

典型归并：

```text
客户端 AT1 测试未通过，不能进入 PV
客户端 AT2 测试未通过，不能进入 PV
车辆 AT1 测试未通过，不能进入 PV
车辆 AT2 测试未通过，不能进入 PV
```

归并后：

```text
AT 测试未通过，不能进入 PV
环节：AT 测试第一轮、AT 测试第二轮
交付域：客户端、车辆
```

### 7.3 展示顺序与内容

风险组排序：

1. 严重等级优先；
2. 流程默认顺序优先；
3. 同一流程环节按风险生成顺序；
4. 无流程映射的历史文本放在末尾。

每个风险组使用独立 Markdown 区块：

```text
**1. 测试周期低于项目最低要求**
环节：PV 测试第一轮、PV 测试第二轮
交付域：客户端、车辆
```

不使用横向竖线拼接风险原因，也不使用依赖固定列宽的风险表格。人员仍使用真实飞书 `<at>` 标签。

### 7.4 信息完整性

- 所有风险组均必须展示。
- 多个环节对应同一风险时只展示一条原因，并列出全部环节。
- 同一环节有多个原因时分别展示。
- 多个交付域均保留。
- 卡片接近飞书元素或字节上限时拆分为连续卡片，并标注“第 N/M 部分”，不得静默截断风险组。
- 普通日报和严重风险卡片使用相同的风险分组器。

## 8. 错误处理与降级

| 场景 | 行为 |
| --- | --- |
| test Webhook 未配置 | 配置错误，停止发送 |
| prod Webhook 未配置 | 配置错误，停止发送 |
| prod 不在 `main` 分支 | 安全错误，停止发送 |
| 展示名称没有真实链接 | 按空值，不报错 |
| 非法非空链接 | 隔离当前需求，继续其他需求 |
| 飞书机器人安全词错误 | 记录 `feishu_error_19024`，按 Webhook 失败处理 |
| 单条需求/节点坏数据 | 隔离当前记录或需求，继续其他需求 |
| 空白编辑行 | 写本地 `WARNING`，跳过，不发数据异常卡片 |
| LLM 不可用 | 使用确定性风险和卡片继续发送 |
| 卡片超出单卡限制 | 拆分为多张连续卡片，保留全部风险组 |

## 9. 测试与验收标准

### 9.1 配置测试

- 默认环境为 `test`。
- test 使用测试 Webhook。
- prod 使用正式 Webhook。
- prod 在非 `main` 分支拒绝发送。
- prod 在 `main` 分支通过分支校验。
- 环境变量和命令行参数优先级稳定。
- 旧单一 Webhook 只兼容 test。
- runtime snapshot 不泄露到日志或 Git 跟踪文件。

### 9.2 链接测试

- 真实 `link`、`url`、`href` 可以被提取。
- 飞书展示文本不会被当作 URL。
- 列表嵌套的 URL 可以被提取。
- 原始完整 HTTP/HTTPS URL 可以被提取。
- 只有展示名称时字段为空且无异常。
- 非法非空 URL 只隔离当前需求。
- 卡片按钮使用真实 URL。

### 9.3 风险测试

- 相同原因的多个环节被合并。
- 相同原因的多个交付域被合并。
- 同一环节的不同原因分别展示。
- AT/PV/线上回归门禁来源正确显示。
- 历史未知原因仍能精确去重。
- 卡片拆分后全部风险组仍存在。
- 所有负责人仍使用真实飞书 @。

### 9.4 端到端验收

1. 在 feature 分支使用测试 Webhook 成功发送 dry-run 和真实测试消息。
2. 在 feature 分支指定 prod 环境时，命令在发送前失败且不调用正式 Webhook。
3. 在 `main` 分支指定 prod 环境时，使用正式 Webhook 发送。
4. 需求链接字段填入飞书文档对象后，卡片按钮跳转到真实文档地址。
5. 需求链接字段只返回文档名称时，需求仍可正常计算和推送。
6. 当前示例风险输出按原因分组，客户端、车辆等环节和交付域完整显示。
7. LLM 关闭或不可用时，基础卡片仍能正常发送。

## 10. 实施顺序

1. 先实现配置模型、环境选择和 `main` 分支安全门。
2. 再实现 repository 层真实 URL 提取和数据异常隔离。
3. 再将风险计算输出补充为结构化 `RiskFinding`。
4. 最后改造 cards 层风险分组、拆分和链接按钮。
5. 更新 `README.md`、`使用说明.md`、示例配置和测试说明。
6. 运行单元测试、卡片快照测试和 test Webhook 集成测试。

## 11. 明确决策

- 采用环境感知配置，不根据 Git 分支自动推断发送环境。
- 默认使用 test 环境。
- 正式环境必须显式指定，并且当前分支必须是 `main`。
- 展示名称不是链接；没有真实链接按空值处理。
- 非法非空链接只隔离当前需求。
- 风险按归一化原因分组，多个环节和交付域合并展示。
- 所有风险组都要展示，超出单卡限制时拆分，不静默截断。
- 不使用浏览器，不增加 Webhook 上行链路。
