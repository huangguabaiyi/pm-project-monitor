# 稀疏环节维护与非阻塞流程提醒设计

日期：2026-08-03

## 1. 背景

当前风险计算会把部分“进展节点表中没有创建对应环节”的情况解释为“该环节没有通过”。例如需求进入版本合入阶段，但没有维护线上回归节点时，系统会直接生成严重风险“线上回归未通过，不能版本合入”。

这种判断能够提供严格门禁，但要求每个项目从开始到结束完整创建全部流程节点。对于中途接入监控、流程裁剪或只维护重点节点的项目，维护成本过高，也无法区分“尚未录入”与“明确未通过”。

本次调整采用稀疏维护模式：门禁判断只基于已经创建的节点；缺少节点本身仅作为非阻塞的流程补充提醒。为保证合板预测完整，当前环节及后续缺少的 AT1、AT2、PV1、PV2、线上回归仍以只读虚拟节点参与排期计算。

## 2. 目标

- 未创建的环节不再被判断为未通过。
- 未创建环节本身不产生门禁风险；只有虚拟排期实际导致预计完成晚于合板、缓冲不足等结果时，才产生对应排期风险。
- 缺少的关键环节在卡片底部合并为一条小字流程补充提醒。
- 已创建节点继续参与状态、排期、延期、缓冲和门禁计算；显式计划完成时间优先，缺失时使用项目配置或固定默认时长。
- 明确存在但未完成的门禁节点仍可阻止进入后续阶段。
- 保持对表格字段类型错误、非法数据和发送失败的现有处理。

## 3. 非目标

- 不自动创建或补齐进展节点。
- 不要求用户维护完整流程模板。
- 不取消 AT、PV、线上回归的业务门禁规则。
- 不修改“已完成”和“已跳过”均视为通过的规则。
- 不修改多语言翻译不阻塞合板的规则。
- 不自动向进展节点表写入虚拟节点。

## 4. 核心语义

### 4.1 节点不存在

节点不存在表示“当前项目未维护该环节”，而不是“环节未通过”。

处理方式：

- 不生成 `RiskFinding`。
- 不生成“未通过”类严重、预警或普通风险原因。
- 虚拟节点按 AT1/AT2/PV1/PV2/线上回归默认 `4/4/3/2/2` 个工作日，或项目配置时长，参与预计完成、缓冲和延期计算。
- 虚拟路径本身不会升级风险；仅当计算结果触发真实排期风险时才影响需求主表的“当前风险等级”。
- 不 @ 节点负责人或项目负责人。
- 不写入进展节点表。
- 在卡片底部的“流程补充提醒”中展示。

### 4.2 节点已经存在

已创建节点继续使用现有规则：

- `已完成`：视为通过，优先使用实际完成时间；没有实际完成时间时使用计划完成时间。
- `已跳过`：视为通过并按零时长计算。
- `未开始`、`进行中`、`已取消`：视为未通过或未完成。
- 显式填写计划完成时间时完全采用人工排期，不再用配置或默认时长延长。
- 缺少计划完成时间时，从计划开始时间或当前计算游标开始，加项目配置时长；项目配置为空时使用固定默认时长。

### 4.3 门禁判断

门禁只校验已创建的相关节点：

- 已创建 AT 节点时，进入 PV 前要求相关 AT 节点通过。
- 已创建 PV 节点时，进入服务端上线、线上回归或版本合入前要求相关 PV 节点通过。
- 已创建线上回归节点时，进入版本合入前要求线上回归节点通过。
- 对应节点完全不存在时，只进入流程补充提醒，不判定门禁失败。

示例：

| 当前环节 | 线上回归节点 | 结果 |
|---|---|---|
| 版本合入 | 不存在 | 不阻塞；提示补充流程 |
| 版本合入 | 未开始 | 严重：线上回归未通过 |
| 版本合入 | 进行中 | 严重：线上回归未通过 |
| 版本合入 | 已完成 | 通过 |
| 版本合入 | 已跳过 | 通过 |

## 5. 流程补充提醒

### 5.1 展示位置

流程补充提醒放在单需求卡片底部，位于严重风险、其他预警和待处理阻塞项之后。它属于维护建议，不属于风险主体。

### 5.2 展示格式

```text
流程补充提醒：尚未维护线上回归、PV 测试第二轮；如项目涉及，请后续补充。
```

展示要求：

- 使用弱化的小字或灰色提示语义。
- 不使用红色标题或严重风险图标。
- 不 @ 任何人员。
- 多个缺少环节合并为一条并去重。
- 按固定业务流程顺序排列，保证每次输出稳定。
- 卡片空间不足时可省略该提醒，不能挤占严重风险和当前节点信息。

### 5.3 提醒范围

只提示与当前阶段有关的关键环节，避免再次要求维护全流程：

- 当前环节本身没有对应进展节点。
- 当前环节之前或当前门禁所涉及的 AT、PV、线上回归节点没有维护。
- 多语言翻译在进入该环节后仍未维护时，可作为流程补充提醒，但不阻塞合板。
- 当前环节之后的普通未来流程不提前提示。

## 6. 风险等级与写回

- 项目风险等级只由真实 `RiskFinding` 决定。
- 流程补充提醒不写入需求主表“风险原因”。
- 流程补充提醒不写入进展节点表“系统风险原因”。
- 如果项目没有其他风险，且虚拟路径未触发延期或缓冲风险，即使存在流程补充提醒，风险等级仍为“正常”。
- 历史已发送卡片和历史风险文本不追溯修改；下次计算使用新规则。

## 7. 数据异常边界

稀疏维护只处理“整条环节记录不存在”的情况，不放宽表格字段格式校验。

以下问题继续按数据异常处理：

- 需求主表必填复选框为空或字段类型错误。
- 已创建节点的状态值不在允许选项中。
- 人员、日期、关联字段无法解析。
- 记录结构无法关联到具体需求。

空白编辑行继续只记录 Warning 并跳过，不阻塞其他需求处理。

## 8. 卡片示例

```text
需求进展｜标准化三期
当前环节：版本合入｜风险等级：正常

当前节点
版本合入｜客户端｜@负责人｜计划 08-27

流程补充提醒：尚未维护线上回归；如项目涉及，请后续补充。
```

如果线上回归节点已经创建但仍在进行中：

```text
严重风险
线上回归未通过，不能版本合入

线上回归｜客户端｜@负责人｜进行中
```

## 9. 测试策略

### 9.1 风险计算测试

- 当前环节缺少节点时不生成门禁风险，返回流程补充提醒，并使用虚拟节点完成排期计算。
- 版本合入阶段完全没有线上回归节点时不生成严重风险。
- 版本合入阶段存在未开始或进行中的线上回归节点时仍生成严重风险。
- AT/PV 节点完全不存在时不生成门禁失败风险。
- AT/PV 节点存在且未通过时继续生成门禁风险。
- 缺少多语言翻译节点不阻塞合板。
- 流程补充提醒本身不改变项目风险等级；虚拟路径触发的真实排期风险仍正常生效。

### 9.2 卡片测试

- 流程补充提醒位于卡片底部。
- 多个缺少环节合并、去重并按流程顺序输出。
- 提醒中不出现 `<at>` 标签。
- 严重风险与流程补充提醒分区展示。
- 卡片达到长度限制时优先保留风险主体，允许省略流程补充提醒。

### 9.3 回归测试

- 显式计划完成时间优先；缺失计划完成时间或关键节点时使用项目配置或默认 `4/4/3/2/2` 时长。
- 已创建门禁节点的通过规则保持不变。
- 数据异常卡片、Webhook 发送和 LLM 降级机制保持不变。

## 10. 验收标准

- 用户只创建当前关注的进展节点，也可以正常生成需求卡片。
- 缺少流程节点不会产生“未通过”类严重风险。
- 缺少流程以一条非阻塞小字提醒呈现，并通过只读虚拟节点参与预计完成、缓冲和延期计算。
- 已创建且未通过的门禁节点仍能准确产生严重风险。
- 项目风险等级、通知 @ 范围和需求主表风险写回不受流程补充提醒影响。
