# 离线配置与严重风险卡片精简设计

日期：2026-07-28

## 1. 背景

当前需求进展监控工具存在两个使用问题：

1. 测试/正式 Webhook、机器人安全词和 LLM 参数部分依赖环境变量，手动运行前需要重复执行 `export`。
2. 严重风险卡片同时展开需求摘要、完整排期公式、节点七列表格、风险原因和负责人汇总，信息重复且卡片过长。

本次调整目标是降低本机运行成本，并把严重风险卡片收敛为可直接决策的结构，同时保持确定性规则、真实飞书 @、风险分类完整性和生产环境保护。

## 2. 目标

- 日常运行只依赖 Git 忽略的 `config.local.json`，不要求预先设置环境变量。
- 同一个本地配置文件同时保存测试和正式 Webhook，并通过运行环境选择使用哪一个。
- 继续支持命令行 `--env test|prod` 临时覆盖默认运行环境。
- 继续阻止非 `main` 分支向正式 Webhook 发送消息。
- 严重风险卡片删除独立节点明细表，改为以风险原因为中心展示。
- 合并语义重复的风险原因，但不遗漏任何风险分类。
- 所有人员继续使用真实 `<at>` 标签。
- 保留关键路径和排期公式，但压缩为单行表达。

## 3. 非目标

- 不修改风险计算口径、工作日算法或延期自然日向上取整规则。
- 不把飞书 CLI 登录凭据写入项目配置文件。
- 不修改多维表格业务字段。
- 不删除环境变量兼容能力，只取消其必需性。
- 不改变 LLM 失效时基础规则仍可正常推送的降级机制。

## 4. 离线配置设计

### 4.1 配置结构

`config.local.json` 作为唯一日常配置入口，结构调整为：

```json
{
  "bitable_url": "https://mi.feishu.cn/wiki/...",
  "runtime_environment": "test",
  "webhooks": {
    "test": "https://open.feishu.cn/open-apis/bot/v2/hook/...",
    "prod": null
  },
  "bot_keyword": "需求进展推送",
  "fixed_rules_path": "固定业务规则",
  "timezone": "Asia/Shanghai",
  "send_hour": 20,
  "send_minute": 0,
  "state_dir": ".state",
  "log_dir": "logs",
  "llm": {
    "enabled": false,
    "base_url": null,
    "api_key": null,
    "model": null,
    "timeout_seconds": 20
  }
}
```

### 4.2 加载优先级

运行环境按以下优先级确定：

1. 命令行 `--env test|prod`。
2. 兼容环境变量 `REQUIREMENT_MONITOR_ENV`。
3. `config.local.json.runtime_environment`。
4. 默认 `test`。

配置值按以下优先级确定：

1. 兼容环境变量覆盖。
2. `config.local.json`。

环境变量保留用于临时调试和旧脚本兼容，但任何正常命令都不再要求环境变量存在。

### 4.3 Webhook 选择

- `test` 环境读取 `webhooks.test`。
- `prod` 环境读取 `webhooks.prod`。
- 旧字段 `webhook_url` 仅作为测试环境向后兼容输入，读取后标准化为 `webhooks.test`。
- 旧的测试/正式 Webhook 环境变量继续作为最高优先级覆盖。
- 未配置当前环境对应 Webhook 时，仅真实发送命令报错；`dry-run`、表结构初始化、状态和日志命令仍可运行。

### 4.4 本地安全

- `config.local.json` 继续保持在 `.gitignore` 中。
- 加载配置时将文件权限收紧为 `0600`；无法修改权限时给出明确错误，避免密钥长期处于全员可读状态。
- `config.example.json` 只保留占位符，不包含真实 Webhook 或 API key。
- `start/restart` 继续生成权限为 `0600` 的运行时快照，LaunchAgent 不直接保存秘密值。
- 正式环境继续执行 Git 分支检查：只有 `main` 分支可以构造并使用正式 Webhook 客户端。

### 4.5 用户操作

配置完成后可以直接执行：

```bash
.venv/bin/requirement-monitor run-once --dry-run
.venv/bin/requirement-monitor run-once
.venv/bin/requirement-monitor start
```

如需临时切换正式环境：

```bash
.venv/bin/requirement-monitor run-once --env prod --dry-run
```

## 5. 严重风险卡片设计

### 5.1 卡片结构

严重风险卡片按以下顺序展示：

1. 项目负责人真实 @ 和严重风险提示。
2. 三行以内的需求摘要。
3. 已填写的需求文档、Meego、多语言翻译按钮。
4. 按风险族合并后的严重风险项。
5. 合并后的其他 Warning。
6. 未完成阻塞项和今日处理动作。

不再展示独立节点七列表格，也不再展示结尾的“相关负责人”汇总。

### 5.2 摘要格式

```text
需求名称｜OKR｜版本｜当前环节
合板 07-28｜预计 07-31｜延期 4 自然日｜关键路径 车辆
计算：PV2 1 工作日 + Bug 修复 1 工作日 + 回归 1 工作日 → 07-31 11:34
```

规则：

- 需求名称与 OKR 相同则只展示一次。
- 不再单独展示计划上线时间，避免与合板和预计完成重复。
- 不再展示完整延期公式；保留延期结果和排期组成。
- Bug 修复预留仍标注“项目配置”或“固定规则默认值”。

### 5.3 风险族归并

在不修改底层风险判断的前提下，卡片展示层按风险族合并：

- **节点延期与缓冲耗尽**：节点已延期、节点延期耗尽节点自身缓冲。
- **测试周期不足**：测试周期低于最低要求、某轮计划周期低于最低要求。
- **合板窗口不足**：最低测试周期无法容纳合板窗口、剩余缓冲为负、预计完成时间晚于合板时间。
- **排期缺失**：缺少测试节点、计划开始或计划完成时间。
- **门禁未通过**：AT/PV/线上回归未达到后续阶段或合板门禁。
- **进展停滞**：长时间无进展更新。
- **阻塞风险**：未解决且影响合板的阻塞项。
- **其他 Warning 区块**：仍有缓冲的节点延期、低缓冲、多语言翻译等非严重风险保留各自名称和影响范围，只在卡片结构上合并到同一区块。

同一风险族合并全部环节、交付域、负责人和安全 DDL。底层每条 `RiskFinding` 仍保留，通知记录、日志和测试仍可追溯原始原因。

### 5.4 风险项格式

```text
1. 合板窗口不足｜严重
影响：PV 第一轮、PV 第二轮｜客户端、车辆
负责人：@负责人A、@负责人B｜最早安全 DDL：07-23
```

规则：

- 负责人根据风险项的环节和交付域关联 `NodeRisk`，去重后使用真实 `<at>`。
- 同一个人在多个节点出现时只 @ 一次。
- 安全 DDL 取该风险族相关未完成节点中最早的 `safe_deadline`。
- 找不到具体环节时显示“项目排期”，不再显示“环节：未标注”。
- 找不到节点负责人时由项目负责人兜底。

### 5.5 严重与 Warning 展示

- 严重风险族逐项展示。
- Warning 风险族合并到一个“其他预警”区块，每个风险族仍保留名称和影响范围。
- 不限制风险族数量；内容超过飞书限制时继续使用现有确定性分片和失败部分重试机制。
- 第一张卡优先保留需求摘要、项目负责人、所有严重风险族和处理动作。

## 6. 兼容性与迁移

- 现有只包含 `webhook_url` 的 `config.local.json` 继续作为测试配置读取。
- 现有环境变量脚本继续工作。
- 第一次读取旧配置时不自动覆写用户文件，仅在文档中提供新结构示例。
- 当前本机 `config.local.json` 迁移为新结构，并写入已提供的测试 Webhook；正式 Webhook 保持空值。
- 卡片变更仅影响展示，不修改风险等级、通知指纹的业务输入或多维表格回写。

## 7. 错误处理

- 配置文件 JSON 无效：启动失败并指出文件和字段。
- 当前环境 Webhook 缺失：真实发送失败，`dry-run` 正常生成卡片。
- Webhook 格式非法：启动失败，不尝试发送。
- 配置文件权限无法收紧：启动失败并给出 `chmod 600 config.local.json` 修复建议。
- 风险项无法关联节点：使用项目负责人和“项目排期”兜底，不丢失风险分类。

## 8. 测试策略

### 配置测试

- 无环境变量时从 `config.local.json` 加载测试 Webhook、机器人关键词和 LLM 参数。
- `--env` 高于文件环境，环境变量保持最高配置值优先级。
- test/prod Webhook 不串用。
- 旧 `webhook_url` 兼容 test。
- 配置权限被收紧为 `0600`。
- prod 非 `main` 分支仍拒绝发送。

### 卡片测试

- 不再生成节点表头和节点明细矩阵。
- 同一风险族合并多个原因、环节和交付域。
- 风险族负责人全部使用真实 `<at>` 并去重。
- 安全 DDL 取相关节点最早值。
- “未标注”替换为“项目排期”。
- 严重风险逐项展示，Warning 合并但分类不遗漏。
- 公式只出现一次，并保留 Bug 修复预留来源。
- 大量风险时仍满足卡片字节、元素和确定性分片约束。

## 9. 验收标准

- 清空相关环境变量后，直接执行 `run-once --dry-run` 可以读取本地配置并生成卡片。
- 直接执行 `start` 可以使用本地测试 Webhook 启动定时任务。
- 非 `main` 分支使用 `prod` 真实发送仍被拒绝。
- 用户示例中的节点明细表消失，九条风险收敛为风险族结构。
- 所有原始风险分类均可在严重风险项或“其他预警”中找到对应展示。
- 卡片中的项目负责人和节点负责人均为真实飞书 @。
- 全量自动化测试通过。
